# GPT-6.2 Sol 提示词写法：如何为视频提示 GPT-6.2 Sol

[English](../prompt-guide.md) · 简体中文 · [← 返回合集](../../README.zh-CN.md)

GPT-6.2 Sol 不直接输出视频。它写代码，通常是用 Three.js 写的单文件 HTML 页面，作者再把页面播放过程录下来。下面的写法来自发布初期作者随帖子公开的提示词，每条都链接到它来自的帖子。合集还年轻，所以这份指南比较短，会随着更多作者公开提示词而增长。

## 1. 写完整的需求：主题、质量要求和交付物

目前公开过的最详细的提示词要求一个 3D 交互式页面，给出主题，要求发挥模型的最高水平，并写明交付什么：

> 请使用 Three.js 创作一个主题为《时间的尽头》的 3D 交互式网页。充分发挥你最顶级的审美、艺术设计和 3D 编程能力，在构图、光影、材质、粒子、动画和空间氛围上做到极致。……请直接完成开发、运行和测试，交付一个真正可玩的作品。

（[@Khazix0918][khazix]，原文即中文）作者对结果的评价是审美"强到爆炸"，并且防御性问题有明显改善。这条提示词点名了渲染方式、氛围和收尾标准（"直接运行和测试"），而设计本身交给模型。

## 2. 需求可以很短，但要点名渲染方式和交互

一句话需求也能用，只要它说清渲染方式，以及观众能做什么：

> 生成一个画面非常逼真的龙卷风，要在threejs 场景里面可以互动

（[@Cayden970207][cayden]，原文即中文。）作者报告这是 GPT-6.2 Sol 在 MAX 设置下一次生成的结果，用时 22 分钟，没有其他规格说明。需求很短；"Three.js"和"可以互动"才是让产出变成可玩场景的关键。

## 3. 对比时用同一条提示词

对比模型时，把完全相同的提示词发给每个模型，并加上让结果可比的约束。有作者用它和 Claude Opus 5.5 比较前端设计：

> 做一个让人看了就想截图分享的网页，主题自定，单文件 HTML，不使用外部图片。

（[@Stargridcompass][stargrid]，原文即中文。）单文件和不使用外部图片的约束，让两个页面可以直接比较。作者报告 GPT-6.2 Sol 的前端审美有非常明显的提升，并请读者判断哪一个更好；帖子本身没有打分。见[模型对比](model-comparison.md)。

## 可以直接用的提示词

```text
把 [主题] 做成一个从磁盘直接打开就能跑的独立 HTML 文件。

画面：[风格、氛围、光照、配色]。
运动：[什么在动、怎么动]。
交互：[鼠标、键盘或点击的行为]。
规则：[场景必须遵守的数字、限制或约束]。

技术：
- 渲染方式：[用 CDN import map 以 ES module 引入的 Three.js，或 Canvas / SVG]。
- 不要外部图片、字体或音频。
- 完成前运行并测试页面，修复发现的错误。
- 只返回完整的 HTML，从 <!DOCTYPE html> 到 </html>。
```

可以到 [Lab 文本竞技场][arena] 里，把这段同时跑在 GPT-6.2 Sol 和其他模型上对比；用 API 的方式见[教程](tutorial.md)。

## 参数设置

- **推理设置。** 有一位作者把自己的运行标注为 "MAX"。这是作者对自己设置的报告；目前还没有关于这个模型各档设置的实测对比。
- **输出预算。** 长页面需要很多输出 token。[教程](tutorial.md)里的 API 示例给的是 `max_tokens: 128000`；想知道一次运行实际用了多少，看响应里的 `usage` 字段。
